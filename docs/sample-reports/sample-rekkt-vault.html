CRITICAL

Reentrancy in withdraw() allows ETH balance drain

CONFIRMED
ID: sol-reentrancy@src/RekktVault.sol:27 Category: Reentrancy Origin: static Location: src/RekktVault.sol:27

An external call or token transfer happens before a later state write in the same function, with no nonReentrant guard. A malicious receiver or ERC-777/hook token can re-enter and act on stale state.

(bool ok, ) = msg.sender.call{value: amount}("");

AI Triage: withdraw() executes an external call to msg.sender before updating balances[msg.sender], allowing recursive calls to drain contract funds.

Recommendation: Apply checks-effects-interactions (update state before the call) and/or OpenZeppelin ReentrancyGuard.

HIGH

Authorization relying on tx.origin enables phishing attacks

CONFIRMED
ID: sol-tx-origin-auth@src/RekktVault.sol:42 Category: Access control Origin: static Location: src/RekktVault.sol:42

tx.origin is the original signer, so any contract the victim interacts with can relay calls that pass this check (phishing-style attack).

require(tx.origin == owner, "not owner");

AI Triage: sweep() relies on tx.origin == owner, enabling phishing attacks via malicious intermediary contracts.

Recommendation: Authorize with msg.sender (or a signature check) instead of tx.origin.

MEDIUM

Unchecked return value of ERC-20 transferFrom

CONFIRMED
ID: sol-unchecked-erc20-transfer@src/RekktVault.sol:33 Category: Unchecked return value Origin: static Location: src/RekktVault.sol:33

Some tokens (e.g. USDT-style) return false rather than reverting. Ignoring the result lets accounting drift from reality.

usdc.transferFrom(from, address(this), amount);

AI Triage: The return value of usdc.transferFrom is not checked or wrapped in SafeERC20, which can lead to silent failure for non-reverting ERC20 tokens.

Recommendation: Use OpenZeppelin SafeERC20 (safeTransfer / safeTransferFrom).
